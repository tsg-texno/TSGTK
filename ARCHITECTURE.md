# Архитектура и следующий этап

React UI → доменная модель/валидация Zod → ProjectRepository → LocalProjectRepository (IndexedDB).
OpenLayers работает в локальной метрической проекции, начало координат слева снизу. Изображение растягивается на введённые физические размеры. Это калибровка по прямоугольнику, без геопривязки WGS84. Объекты хранятся в GeoJSON-подобной геометрии, окружение и стили — в собственном версионированном JSON. Шаблоны символов — собственные SVG, без заимствования ресурсов Arma.

`src/domain.ts`: схемы проектов, объектов и контекста; роли; согласованные справочники линий/зон и совместимость прежних объектов.
`src/repository.ts`: интерфейсы репозитория, IdentityProvider и CollaborationTransport. Сетевых запросов к TSG нет.
`src/atlas.ts`: проверка конфигурации и обязательный белый список перед созданием источника тайлов.
`src/MapEditor.tsx`: проекция, слои, рисование, выделение, изменение вершин, привязка к существующим вершинам.

## Изоляция

Ровно 2 идентификатора серверов × 4 нейтральных идентификатора сторон. Названия сторон TSG не предполагались. Для каждой пары отдельная IndexedDB. Сохранение проверяет совпадение scope, импорт отказывается принимать чужой scope, чтение дополнительно фильтрует scope. В экспорте одна операция и только её объекты. Общих слоёв четырёх сторон нет.

**Локальный переключатель сторон — не защита от владельца браузера.** Пользователь устройства может открыть все локальные базы и выбрать любую роль. Это организация локальных данных и защита от случайного смешивания, не серверная авторизация. На общем компьютере не хранить секретные планы разных сторон в одном профиле. Для реального разграничения необходимы TSG identity + membership и серверные проверки. КС также не должен автоматически получать доступ к чужой стороне.

## FastAPI / PostgreSQL (проект контракта, ещё не реализовано)

Сетевой адаптер ProjectRepository заменяет IndexedDB, UI остаётся прежним. Сервер устанавливает user ID, роль и доступные membership только по проверенной сессии API TSG; значения в JSON/URL не являются доказательством доступа. Идентификаторы серверов/сторон должны быть согласованы с TSG.

Предлагаемые маршруты:

- `GET /v1/session` → user, memberships, role, allowed scopes, capabilities.
- `GET /v1/servers/{server}/sides/{side}/projects`.
- `POST /v1/servers/{server}/sides/{side}/projects`.
- `GET|PUT|DELETE /v1/servers/{server}/sides/{side}/projects/{id}`; обновление с If-Match/ревизией, конфликт → 409.
- `GET /v1/config/maps` → серверный белый список и одобренные источники.
- `WS /v1/servers/{server}/sides/{side}/projects/{id}/events`.

PostgreSQL: `memberships(user_id,server_id,side_id,role)`, `projects(id,server_id,side_id,phase,revision,document jsonb,created_by,updated_at)`, `project_events(project_id,server_id,side_id,revision,actor_id,payload jsonb)`. Для всех объектов составные FK `(project_id,server_id,side_id)` к UNIQUE на projects. Включить и FORCE ROW LEVEL SECURITY на таблицах, использовать DB роль без BYPASSRLS. Контекст транзакции устанавливается только сервером из проверенной сессии, сбрасывается с окончанием транзакции. Сервисный суперпользователь не используется в запросах клиентов. Обязательно интеграционно проверить горизонтальный доступ по чужому id, экспорт, media URL, журнал и ошибки.

WebSocket: авторизация до подписки, канал строго `(server, side, project)`; повторная проверка членства и отзыв сессии; каждое событие содержит revision, eventId, actorId, projectId, scope. Проверять разрешение записи для каждого события, не только при подключении. Боец читает, штабист и КС редактируют (предварительная матрица, уточнить в TSG). Отправка только после commit транзакции. Очередь на отправку, reconnect и конфликты — следующий этап, не скрытая функция текущего клиента.

Синхронизация по умолчанию отключена. Даже после реализации разрешать только planning/debrief, пока TSG отдельно не утвердит иной режим. Запрет должен обеспечиваться на сервере, одного client feature flag недостаточно.

## Ограничения первой версии

Нет реального backend, входа TSG, совместного редактирования, загрузчика пакета тайлов, кругов/прямоугольников как отдельных примитивов и печатного экспорта. Семь зон — семь способов оформления многоугольника; семь линий — семь вариантов оформления ломаной. Названия теперь сверены с полным прежним обсуждением; старые объекты помечаются отдельно от нового набора. История отмены хранится только в памяти для объектов, до 50 шагов; не распространяется на замену карты. Экспорт включает исходное пользовательское изображение, поэтому файл может быть крупным. Браузерная квота может ограничивать хранилище; ошибка сохранения видна в интерфейсе, JSON-экспорт остаётся доступен.
